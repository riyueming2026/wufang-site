# スケジュール更新の手順書（会話エージェント用）

伍芳さんのサイトのスケジュールを、会話で追加・変更・削除するときの手順です。
更新を依頼するのは、現在は「あきさん」が、伍芳さん本人の依頼を受けて代理で行います。

## 基本の考え方

- 情報は **ひとつずつ確認してから** 書き込む。推測で補わない。
- 書き込みは必ず `tools/schedule.py` を通す（直接 `data/schedule.json` を編集しない）。
- 公開してよいのは、**伍芳さん本人が最終内容に OK を出したあと** だけ。
- 間違えたら `schedule.py rollback` で1つ前の状態に戻せる。

## 会話の流れ

### 1. 聞き取り

依頼は、次のどれでも受け付ける。

- 文章（例:「12月20日に〇〇ホールでコンサート、14時開演」）
- チラシや記事の画像
- 既存の予定の変更（「完売になりました」「中止になりました」）

次の項目を取り出す。

| 項目 | 内容 | 必須 |
|---|---|---|
| 種別 `--cat` | Concert（演奏会）／ Media（出演・掲載）／ Others（教室・イベントなど） | ○ |
| 日付 `--date` | `2026.12.20` の形（0埋め） | ○ |
| 題名 `--title` | 公式の表記どおり | ○ |
| 詳細 `--time` | 開場・開演時間、会場など（1行） | |
| 状況 `--status` | 完売／キャンセル待ち／定員となりました／中止／延期 | |
| リンク `--url` | 詳細ページや予約ページ（http から） | |

### 2. 不足と矛盾の確認

次の点を、**かならず確認する**。分からないことは、本人に質問する。

- 年が書かれていない → 年を質問する（「今年」と決めつけない）
- 日付と曜日が合わない（例:「12月13日(土)」だが、実際は日曜）→ どちらが正しいか質問する
- 開演時間・会場が抜けている → 質問する。「未定」なら、詳細欄を空にする
- 同じ日に似た予定がすでにある → 変更なのか、別の予定なのかを質問する
- 題名が長い、略称が多い → 公式表記を確認する

質問は、まとめて1回で聞く。何度も分けて聞かない。

### 3. 下書きの確認（まだ書き込まない）

必ず `--dry-run` で、内容と、表示される場所を確認する。

```
python3 tools/schedule.py add --date 2026.12.20 --cat Concert \
  --title "〇〇コンサート" --time "14:00開演　〇〇ホール" --dry-run
```

出力された「追加する内容」（曜日つき）と「表示される場所」を、そのまま本人に見せて、
**「この内容で公開してよいですか？」** と聞く。

### 4. 本人の OK のあとに、書き込む

`--dry-run` を外して実行する。続けて、次の3つを行う。

```
python3 tools/schedule.py validate     # 全体の検査
python3 build.py                       # index.html を作り直す
```

そのあと、公開する。変更したファイル（`data/schedule.json`、`index.html`、`history/`）を commit して、`main` へ push する。GitHub Pages が、数分で自動的に反映する。

### 5. 結果の報告と、巻き戻し

- 何を追加・変更・削除したかを、1〜2文で報告する。
- 間違いがあれば、`python3 tools/schedule.py rollback` で、1つ前に戻して、再度ビルド・公開する。

## 変更・削除

- 変更: `schedule.py list` で id を調べ、`schedule.py set ID --status 完売 --dry-run` で確認 → OK 後に `--dry-run` を外す。
- 削除: `schedule.py remove ID --dry-run` で確認 → OK 後に実行。**削除は、本人が明確に依頼したときだけ**。
  終わった予定は、削除せず、そのまま残す（自動で「これまでの予定」へ移る）。

## してはいけないこと

- 本人が確認していない情報を、書き込まない・公開しない。
- 電話番号、メールアドレス、個人名を、予定の詳細に書かない（問い合わせは、サイトの Contact ページへ）。
- 依頼されていない既存の予定を、書き換えない。
- チラシの文字が読み取れないとき、推測で埋めない。読み取れた部分と、読み取れなかった部分を、分けて伝える。
- 日付の検査に引っかかったら、無視せず、本人に確認する。

## データの形

`data/schedule.json` の1件分:

```json
{ "id": "20261220-concert", "d": "2026.12.20", "c": "Concert",
  "t": "題名", "u": "https://...", "s": "", "m": "14:00開演　会場名" }
```

`id` は自動で付く。`s` は状況、`m` は詳細、`u` はリンク（空でもよい）。
